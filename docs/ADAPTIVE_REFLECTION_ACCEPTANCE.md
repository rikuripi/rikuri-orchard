## Ownership and conflicts

Orchard remains a software-domain experience over the future shared Rikuri services. The current prototype store remains separate; no migration or new production identity/policy/scheduler/knowledge authority is added. Pi Foundation Stage 01 already owns encrypted custody and managed restore; source “Stage 1” cannot postpone them. Product Stage 1 readiness is proposed before expanded ingestion; source remote/family/advanced phases map to Pi 3/4/6/7/8/10, preserving creative-studio Stage 2. Orchard historical O stages do not override M0–M6.

Rikuri/owner authority and trusted enforcement remain separate from worker intelligence. Pi's OpenShell-first Ubuntu candidate, credential-free Foundation workers and requirement for a proven Local Only no-network path control over source Docker-first or generic private-device wording. Full Rikuri integration and qualification remain Not yet proven. SQLCipher, per-vault wrapping, Podman/OpenSandbox/microVM/GPU technologies are candidates, not dependencies. Keep per-deletion-unit forgetting and current-revocation restore semantics. No administrator-proof privacy claim from encryption, a shared GPU, container or VM.

TaskContract v1 and the observation bridge stay unchanged. Future versioned capability profiles bind model/revision/quantization, native harness/runtime, tools/skills/context, task class, uncertainty and expiry. Guided/hybrid/model-directed orchestration can change strategy only, never permissions, independent acceptance, application approval, hard budgets or repair ceilings. One reflective worker is preferred when sufficient; existing delegation authorization remains. A failed experiment is evidence, not canonical truth. Persistent lessons require validated promotion; model-weight training requires a later explicit consent/licensing decision.

## Experiment and promotion receipt

Record fixed task/acceptance baseline, permitted paths/capabilities, exact execution and skill identities, independent verifier, resource ceilings, stop rule, run/parent IDs, candidate/checkpoint digests, outcomes/failure and intervention, privacy/retention, measured resource values and unknowns, reviewer disposition, promotion decision and rollback target. Compute verified utility delta per minute/token/energy/dollar separately; ratios require nonzero measured denominators. Minimize prompts/private payloads and do not capture unrestricted internal reasoning for future learning.

The supplied AREX text describes task-time revision and uses an optimized harness; it does not show continuous weight updates or universal autonomous reliability. Skills and extra rounds are partly confounded. Adaptive design is Rikuri's proposed experiment, not a reproduced paper result. No new model call, account spend, plugin install or experiment is authorized by this document.
